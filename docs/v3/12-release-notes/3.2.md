# v3.2: Release Notes

> **Covers:** v3.2.0 to v3.2.84 (2026‑06‑11 to 2026‑09‑21)
> **Audience:** All users. Items relevant only to administrators are marked.

This page summarizes the ***TrustSource*** v3.2 series, dominated by a major
overhaul of **Threat Modelling**. For the complete, version-by-version list
of every change, see the
[CHANGELOG](https://github.com/eacg-gmbh/ts-app/blob/develop/CHANGELOG.md)
in the repository.

## Added

- **Threat Modelling** gained an AI-driven generation agent: a **Generate**
  button starts an automated run that builds the system model, identifies
  risks and develops countermeasures, with a live progress panel (status,
  elapsed time, per-phase progress) instead of a plain spinner. You can now
  choose which **stage** to run (build model only, generate risks only,
  develop countermeasures only, or the full pipeline), and re-run any single
  stage from the model's **Lifecycle** menu without starting over. See
  [Threat Modelling](../03-internal/08-threat-models/index.md) for the
  current workflow.
- The threat model is shown as an interactive **Data Flow Diagram** (pan,
  zoom, fit, auto-layout, SVG/PNG export, fullscreen, dark mode). Manually
  arranged node positions are now saved and preserved across reloads and
  re-runs, and diagrams with many vulnerabilities cap badges at five with a
  "+N more" expandable list.
- Project Settings can now populate a project's **Application goals** by
  uploading an `architecture.md` file instead of retyping it; uploads are
  automatically screened for prompt-injection attempts before use.
- New risk origin **"Threat Model Assessment (TMA)"** for risks created by
  the threat-model agent, with full threat-model context (STRIDE/ENISA
  categories, CWEs, trust-boundary crossing) shown wherever the risk is
  viewed or edited.
- Requesting an **approval** is now near-instant: the request is created
  immediately and you're taken to the finalize page, where the Compliance
  Report, SoUP, Notice and SBOM documents generate in the background with a
  live per-document progress view.
- New read-only REST endpoints for imported SARIF test results.
- **Operational BOMs (OBOM)**: a module with an OBOM gets an **OBOM** tab
  listing the containers, platforms and runtimes it runs on, and the project
  and module lists gain an OBOM column. Available with the `obom` license.
- Threat model **Download** offers a choice: **TrustSource (complete)** or
  **OTM (spec-compliant)** for tools that validate strictly against OTM
  v0.2.0. The diagram is easier to read on large models: flow labels start
  hidden (a **Labels** button brings them back), clicking a component
  isolates it and its connections, and zones carry a title bar with their
  trust rating.
- **CWE on test findings**: SARIF findings show the weaknesses the tool
  reported, with a CWE column on the tests overview. A security manager or
  account admin can assign a weakness by hand to a rule that reports none.
- Projects can keep their risk register in step with SARIF scans: switch on
  **Create risks from SARIF weaknesses (CWE)** in project settings. It is
  off by default and applies to future imports only.
- A component the scan could not match to a license can be given one by hand
  in the module's dependency view, with a required justification. The license
  catalogue gained `PUBLIC-DOMAIN` and `UNKNOWN`; a manual license files a risk
  with the new origin **Unmatched License (LIC)** (Risks feature).
- Projects can push newly matched CVEs to **Webhooks and Channels** (three
  switches on the project's tab). Webhooks can subscribe to "Vulnerabilities
  by module", and alerts name where each affected component is used and which
  versions it can be upgraded to.
- **Sign in with TrustSource**: TrustSource can act as a login provider for
  AWS Cognito, Azure AD, Auth0 or Keycloak, issuing an identity token with the
  user's company and roles.
- **DeepScan results** started from the Component Manager open inside
  TrustSource: the scanned repository, its file tree, and the license and
  copyright findings per file.
- The **components lake** asks where to search first (registry (public
  component index), internal (your company's components) or Component
  Manager (the full database)), and the search is part of the page address,
  so it survives a reload and can be shared. See
  [Component lake](../05-knowledge/01-component-lake.md).
- A **version filter** above the versions table on component, COTS,
  infrastructure and Component Manager edit pages; **Critical Components**
  gained tabs for Deb, CocoaPods, Apk, Cargo, Dart and Go.
- The scan import form asks for the **module name**, prefilled from the file.
  `moduleName` and `projectName` are accepted by scan, SBOM import and SARIF
  upload alike.
- Selecting a point in the "Risk overview: CVSS vs EPSS" chart scrolls to and
  highlights that finding; the chart now zooms to the findings it shows.
- New API endpoints list a company's approval requests (by status and
  assignee) and store a CSAF 2.0 document as a draft for review.

## Improved

- **Administrators:** accounts that are suspended (by an operator) or
  automatically flagged as suspicious are now blocked at sign-in and,
  within seconds, locked out of any already-open session; suspension is
  managed outside the main application, not from a page inside TrustSource.
- New self-service registrations are now plausibility-checked; a flagged
  sign-up doesn't receive the verification link and is asked to contact
  support instead. Genuine sign-ups are unaffected.
- Company API keys and external integration credentials are now encrypted
  at rest. Nothing changes for you: the masked key view and copy button
  work exactly as before, and every copy is recorded in the audit log.
- The Administration menu's **Integrations** entry (GitHub, Jira, TFS,
  SCANOSS, Webhooks, LeanIX), briefly dropped during a menu restructure, is
  back.
- Requesting a password reset or an invite/enrollment email now works
  reliably when an email address is attached to more than one account.
- Project names are stored trimmed and matched trimmed, and every upload
  route (scan, BOM import, SARIF, OBOM, Check) resolves a name to the same
  project. Creating a project in the UI refuses a name already used in the
  company; creating one through the API returns the existing project instead
  of a duplicate.
- A scan no longer fails because of one unusable dependency: the entry is
  skipped, the rest is processed, and skipped entries are recorded on the
  scan and in Company Logs. Dependency trees nested more than 80 levels deep
  and deeply nested content elsewhere in an upload are refused with `400`
  naming the limit; uploads over the limit (50 MB by default) with `413`.
- Submitting a scan is about 45% faster, so bursts of large scans no longer
  time out.
- Test results: CodeQL findings are counted, passing results are no longer
  counted as findings, findings without a stated severity show as warnings,
  and uploaded SARIF tests read "Passed" or "Failed" instead of "Unfinished".
  Counts on documents imported earlier may therefore drop.
- Suspending a user or removing them from a company ends their logins for
  good; reinstating the account does not bring the old session back.
- Corporate login accepts the realm name as well as the company id or name.
- A CVD case carries the vulnerability type and impact as fields of their own.

## Fixed

- Component index search (used when adding a component) no longer collapses
  differently-versioned packages that share a display name into one result.
- The license pickers on a component's edit page now work on a hard refresh
  or bookmarked link, not only when navigated to from inside the app.
- The "Change selected license" dialog for multi-license components no
  longer sometimes opens twice.
- Creating an API key can no longer give you two identical keys; the
  button shows progress and cannot be triggered twice.
- Several clicks on **Create** no longer create several projects at once.
- Corporate (Keycloak) sign-ins that come back incomplete return you to the
  login page; new Keycloak users keep the roles their account grants.
- The "Risk overview: CVSS vs EPSS" chart shows real EPSS scores for
  projects with more than 1000 distinct CVEs.
- Signing in as another user without reloading no longer leaves the previous
  user's data behind.
- "Copy details" and "Create issue" work on components that carry only a
  package key, and are reachable by keyboard.
- Find CWE accepts "CWE-551", "cwe-551", "CWE:551" and "cwe551". Opening a
  weakness through a shared link works.
- Vulnerability subscriptions: a failed request no longer leaves **My
  Subscriptions** spinning or reports a false success.
- COTS and infrastructure component pages (details, Info, CPE, Crawlers,
  Logs) open again.
- The crawler fills in missing licenses on component versions again.
- DeepScan pages show clear messages when a result is unavailable or the
  service cannot be reached, instead of spinning forever.
- Dropdown menus opened from a page header are readable in light mode.

## Security

- **Administrators:** if your enterprise account uses the company switcher
  or the enterprise company list, rotate the affected companies' API keys,
  CSAF feed keys and integration tokens after upgrading: a prior version
  could expose sibling companies' credentials to enterprise admins browsing
  that list. See the CHANGELOG (3.2.14) for details.
- Hardened the real-time data connection so it can only be opened from the
  TrustSource site itself, closing a path where a leaked session token
  combined with a third-party page could act on a user's behalf.
- Hardened the Jira, TFS and webhook integrations against saving or calling
  a URL that points at an internal, private or cloud-metadata address.
- User-administration data returned to the app no longer includes password
  hashes or enrollment/reset/session tokens.
- Messages, status changes and approvals are now strictly scoped to the
  posting user's own organization; a reference to another organization's
  project or module is rejected instead of silently applied.
- A user can no longer move their account into another company by editing
  their own profile, and self sign-up is limited to 10 attempts per hour per
  address.
- Webhook and channel URLs pointing at private, loopback or cloud-metadata
  addresses are refused when saved; **review existing entries** before turning
  vulnerability alerts on. Webhooks are visible only to account admins,
  managers and compliance managers.
- Project calls through the API no longer return integration credentials
  (Jira, TFS, GitHub); **rotate any credential stored on a project**.
- Names, branches, tags, repository names and dialog messages are shown as
  text instead of being run as HTML; legal document links open only for
  http(s) addresses.
- Check, release comparisons and public VEX feeds read only the owning
  company's data; REST file uploads without an API key are refused (`401`).
- Revoking an application's access from profile settings takes effect
  immediately.
- Users can no longer forge entries in a component's change history, and
  password-reset, verification and invitation links are no longer logged.
