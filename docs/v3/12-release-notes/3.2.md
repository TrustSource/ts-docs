# v3.2: Release Notes

> **Covers:** 3.2.19 to 3.2.83 (2026-06-25 to 2026-09-20)
> **Source:** the [Updates](../08-personal/01-updates.md) feed in ***TrustSource***.

This page follows the entries of the **Updates** feed for the v3.2 series, newest first. Items are grouped as in the feed under **New**, **Improvement** and **Fix**.

## 3.2.83 (2026-09-20)

### New

- **TrustSource as login provider (OIDC):** connected systems can offer "Sign in with TrustSource" and receive a signed identity token that carries the user's active company and roles. It is off until it is configured for a connecting application.
- **Alerting:** projects can push newly matched vulnerabilities to your own webhooks, Slack or Microsoft Teams channels. Per-project switches cover the project itself, its releases, and whether alerts also reach company-wide receivers. Alerts name where each affected component is used and which versions it can be upgraded to. See [Webhooks and channels](../06-administration/08c-webhooks-channels.md).
- **Legal:** a component the scan could not match to a license can be given one manually, with a required justification and a visible record of who set it and when. New catalogue entries "Public Domain" and "Unknown" cover more cases. See [Manual license resolution](../03-internal/02-modules/06-manual-license-resolution.md).
- **Software quality and risk:** projects can keep their risk register in step with SAST scans. Switch on **Create risks from SARIF weaknesses** to keep one risk per weakness and tool automatically, without overwriting what you already triaged by hand. See [SARIF weaknesses](../02-inbound/04a-sarif-weaknesses.md).
- **CVD:** a CVD case carries the vulnerability type and impact as searchable fields of their own, not only as text in the description. See [CVD cases](../04-outbound/06-cvd-cases.md).

### Improvement

- **CSAF:** the public vulnerability feeds (VEX/CSAF) and the Check feature match consistently against the current vulnerability database and stay within your own company's data.
- **SCA:** the scan details header shows the number of binary links instead of the full list; the dialog keeps long links readable.
- **Projects:** creating a project is idempotent. Sending the same request twice returns the existing project instead of a duplicate, and project names are trimmed and matched consistently.
- **SCA:** one bad or oversized item in an uploaded scan no longer stops the whole upload. It is skipped and recorded, and the rest of the scan is processed and analysed.
- **Security:** signing in with Keycloak keeps the roles your identity provider grants, also across several tabs and reconnects.
- **UI:** switching accounts without reloading the page no longer leaves the previous user's data on screen.
- **Security:** several account-integrity, cross-site-scripting and data-isolation issues were closed. Self-registration is rate-limited (10 attempts per hour per address) and can be switched off. Password-reset, verification and invitation links are no longer written to server logs. REST file uploads require authentication before any content is read, reject oversized files, and are always served back as downloads. Webhook and channel destinations that point at internal or cloud-infrastructure addresses are rejected, and webhooks and channels are visible only to the roles that can create them. The server needs an explicit encryption key to start.

> [!WARNING]
> **Action required** if you use Jira, TFS or GitHub integrations on your projects: an API response included these integration credentials where it should not have. Rotate the stored integration credentials as a precaution.

### Fix

- **Crawler:** missing license information on component versions is backfilled again.
- **Vulnerability risk:** the "Risk overview: CVSS vs EPSS" chart shows accurate scores again for projects with more than 1,000 distinct CVEs.
- **UI:** header dropdown menus are readable again in light mode.
- **Security:** revoking an application's access takes effect immediately, also for a sign-in already in progress.

## 3.2.63 (2026-09-02)

### New

- **Threat modelling:** support for OBOMs. An OBOM records how something is operated: the containers, platforms and runtimes it runs on. It can be derived from IaC information such as Terraform, OpenTofu or AWS CloudFormation and is uploaded by ts-scan with the usual dependency scan. A module with an OBOM gets its own OBOM tab, and project and module lists show an OBOM column. Also available through the REST API; availability depends on your company's OBOM entitlement. See [OBOM tab](../03-internal/02-modules/07-obom-tab.md).
- **Threat modelling:** SARIF/SAST test findings show the CWE weaknesses each tool reported, with a company-wide CWE column, breakdowns by weakness, and the option for a security manager to assign a weakness to a rule the tool left unclassified. See [SARIF weaknesses](../02-inbound/04a-sarif-weaknesses.md).
- **Threat modelling:** downloading a model offers a spec-compliant **OTM export** next to the full TrustSource export, for tools that validate strictly against OTM v0.2.0.
- **Critical components:** new tabs for Deb, CocoaPods, Apk, Cargo, Dart and Go, so components of ecosystems without a dedicated crawler can be reached from the Critical Components view.
- **Versions filter:** a version filter sits above every **Versions** table (component details, COTS and infrastructure components), so you no longer page through all versions to find one.
- **Scan import:** the import form asks for the module name first (prefilled from the uploaded file, editable), so an SBOM lands on the module it describes. See [Import scans](../02-inbound/02-import-scans.md).

### Improvement

- **Threat modelling:** the Data Flow Diagram is much easier to use on large, generated models. Flow labels start hidden and appear for what you focus on, clicking a component isolates it and its connections, names wrap sensibly, trust zones show their rating with a legend, and the diagram fills the available space.
- **Performance:** scan submission is about 45% faster, and scan analysis no longer re-reads the whole component catalogue for every dependency.
- **Software quality:** test and finding counts are more accurate. Passing or informational results (for example from CodeQL) no longer count as violations, findings without a severity show as warnings, and a weakness assigned by a person is never confused with one a tool reported.
- **Software quality:** creating an issue or risk from a test finding starts with the rule's own description and uses the project's configured repository.
- **User experience:** the Quality, Legal and Security columns on project and module lists show a dash for anything never measured, instead of "0".

### Fix

- **User experience:** creating a project no longer creates duplicates when the Create dialog was opened more than once on the same page. Duplicates created before must be removed by hand.
- **User experience:** creating an API key can no longer issue two identical keys on a slow connection or a double-click; **Create** shows progress and cannot be triggered twice.
- **User experience:** a corporate (Keycloak/SSO) login with an incomplete callback returns you to the login page instead of a dead-end page.
- **User experience:** opening a weakness (CWE) from a bookmark, a shared link or right after signing in no longer stops at "Authentication required".
- **Software quality:** in SARIF/SAST uploads, an unusual rule name no longer stops the upload, the test status (Passed, Failed, Unfinished) reflects what the tool reported, and the **Rules** count reflects what was checked.
- **Software quality:** a dependency scan and a SARIF upload for the same component no longer create two modules with the same name.
- **CSAF:** the CSAF removal button is disabled while the first request runs, so a removal can no longer be sent twice.
- **Components:** COTS and infrastructure component pages and their Info, CPE, Crawlers and Logs screens open correctly again, also from old links.
- **Legal compliance:** a module's root-component license selector is always available and works for modules with more than one root component.

## 3.2.46 (2026-08-25)

### New

- **Vulnerability management:** clicking a point on the "Risk overview: CVSS vs EPSS" chart scrolls the findings list to that finding and highlights it briefly. See [Vulnerability report](../03-internal/04a-vulnerability-report.md).
- **DeepScan:** DeepScans can be viewed inside ***TrustSource***. A read-only page shows the scanned repository, its file tree and the license and copyright findings per file. Links can be shared and bookmarked down to a single file, and older scans open too.

### Improvement

- **Component Lake:** redesigned. Choose first whether to search the public component registry, your own company's components or the full component database. The search runs when you submit it, and it is part of the page link, so it survives a reload and can be shared. See [Component Lake](../05-knowledge/01-component-lake.md).
- **Component Lake:** search results show licenses, homepage and repository links. The component index detail page shows Maven coordinates, version details, checksums, and vulnerability findings with severity scores and colours instead of "n/a".
- **Component Lake:** the ecosystems match what ***TrustSource*** scans (Maven, Cargo, Dart, Go, Gradle, npm, NuGet, PyPI), with icons for Cargo, Dart and Go.
- **Vulnerability management:** the "Risk overview: CVSS vs EPSS" chart zooms to the findings it shows instead of always spanning the full scale.
- **Vulnerability Lake:** Find CWE accepts the common ways of writing a CWE id (for example `CWE-551`, `cwe-551`, `CWE:551`, `cwe551`), also in shared or bookmarked links.
- **Details view:** a module's view updates by itself when analysis settings change or a new scan arrives.

### Fix

- **Issue tracking:** **Copy details** and **Create issue** in the Tasks panel of module dependency, component and license views work reliably again, respond to the icon and its label, work with keyboard and screen readers, and appear as one consistent control.
- **Issue tracking:** tickets created from a finding (Jira, GitHub, TFS) no longer contain garbled or incomplete text. See [Issue trackers](../06-administration/08a-issue-trackers.md).
- **Legal compliance:** a license chosen for a module's root component is applied even when the scan recorded no dependencies for that component.
- **DeepScan:** **Refresh** works while a scan runs or after it fails, a scan with a bad or unknown link shows an error instead of spinning, and dark-mode readability was fixed.
- **Vulnerability Lake:** **My Subscriptions** no longer spins forever or reports a subscription as created or removed when the request failed; short service interruptions are retried.

### ts-analysis 3.7.6 (2026-08-25)

- **Legal compliance:** the analysis respects private licenses in root components.

## 3.2.40 (2026-08-19)

### New

- **Vulnerabilities:** vulnerability reports start with a CVSS vs EPSS risk-overview chart that plots every finding by severity and real-world exploitation probability, on screen and in the exported PDF. See [Vulnerability report](../03-internal/04a-vulnerability-report.md).
- **Vulnerabilities:** new read-only REST endpoints expose environmental CVSS context and threat model data for external tools.
- **App security:** new self-service sign-ups are checked for plausibility; flagged sign-ups are asked to contact support instead of being activated. Suspended accounts and accounts flagged as suspicious cannot sign in, including active sessions, until an operator releases them.
- **Threat modelling:** upload an `architecture.md` file in the project settings to fill in the project's application goals, also through the REST API. The content is screened for prompt-injection attempts by a pattern check and an AI-based check.

### Improvement

- **Threat modelling:** the live-progress panel during model generation is clearer and more reliable, with readable phase names and status icons per phase. The generated Data Flow Diagram has resizable trust zones, cleaner connector routing and flow-direction indicators.
- **Compliance:** requesting an approval is near-instant. The request is created at once, and the documents (Compliance Report, SoUP, Notice, SBOM) are generated in the background with progress shown on the finalize page.
- **CSAF/VEX advisories:** internal module identifiers can no longer be recovered from or forged into a published advisory; existing advisories keep working.
- **App security:** API keys and external service credentials (for example integration credentials) are encrypted at rest. Existing keys are upgraded the next time they are used, and every key copy is recorded in the activity log.

> [!IMPORTANT]
> **Action may be required:** creating, importing or exporting a CSAF advisory requires the role Compliance manager, Manager, Security manager or Account administrator, enforced on the server. Some accounts may lose access they had through the interface before; check whether affected users need a role update. See [Roles overview](../10-roles-permissions/01-roles-overview.md).

### Fix

- **API keys:** the copy button no longer puts "undefined" on the clipboard when a stored key cannot be read back; it explains why the copy failed. See [API keys](../06-administration/04-api-keys.md).
- **Identity management:** a corporate (SSO) login reports an error naming the realm when the identity provider issues a token without required claims, and the login page accepts your company's configured realm name.
- **API:** the public SBOM and Notice endpoints return 404 or 500 instead of "200 OK" when a document cannot be produced.
- **Reports:** the CVE impact report shows GitHub Security Advisories (GHSA), and CWE search in the Vulnerability Lake works again.
- **SPDX import:** SPDX SBOM imports keep the full dependency hierarchy and record license information, the same as CycloneDX imports.
- **SBOM import:** SBOMs with cyclic or very deep dependency graphs (common in container and distribution images) import successfully.
- **User import:** the CSV import preview no longer changes roles before the import is confirmed. Importing users by CSV requires the Account administrator or Manager role.
- **User interface:** several pages no longer show "Authentication required" on a direct load or refresh, the license dropdowns on a component's edit page work on a direct load, and billing details apply right after saving.
- **Sign-up:** e-mail verification links for new users no longer report as expired.
- **Support:** the support widget loads again.
- **App security:** a company's Open Source Policy document can no longer be pointed at another uploaded file, and notification pop-ups always render as plain text.

## 3.2.19 (2026-06-25)

### New

- **REST API:** new endpoints to read imported SARIF test results. `/core/tests/sarif` lists the imported SARIF documents with their tool (for example semgrep), import date and number of findings per severity, filterable by origin, project, module, scan or analysis. `/core/tests/sarif/{id}` returns one document with its full SARIF content. See [Tests](../09-rest-api/endpoints/tests.md).
- **Threat modelling:** a **Threat Model** button on the project modules page starts AI-driven threat model generation (with the Threat Modelling license, for managers and compliance managers). While it runs, the button shows a spinner and the page reports completion or failure. See [Threat model agent](../13-capabilities/07-threat-model-agent.md).
- **Threat modelling:** arrange a generated diagram by dragging its nodes and keep the arrangement with **Save layout**. The project setting **Layout on next analysis run** chooses whether the next run keeps your layout (default) or rebuilds the diagram.
- **Threat modelling:** the **Generate threat model** dialog has a stage selector: **Run all** (default; builds the model, generates risks, then develops countermeasures), **Build model**, **Generate risks** or **Develop countermeasures**. See [Run modes](../03-internal/08-threat-models/04-run-modes.md).
- **SBOM report:** the CycloneDX export menu of an SBOM file's details page offers **AIBOM (AI / ML)** next to the SBOM and CBOM exports.

> [!NOTE]
> Threat modelling requires a specific license. If you do not see the option, ask your account manager for a trial or a quote.

### Improvement

- **REST API:** `GET /core/risks` with `moduleId` returns every risk attached to the module, and with `projectId` the project's own risks together with the risks of all its modules. Each risk is returned once. Without `projectId` or `moduleId` the endpoint answers 400. See [Risks](../09-rest-api/endpoints/risks.md).
- **REST API:** the `origin` of a risk is validated. Accepted values are empty, `SDLC`, `SQ`, `SSC`, `CVE`, `YARA`, `CWE`, `TD`, `TMA Assessment` and, for compatibility, `threat-model`; other values are rejected with 400.
- **Threat modelling:** the new risk origin "Threat Model Assessment (TMA)" can be selected when adding or editing a risk and is used for risks created by the threat model agent. The threat model context (STRIDE categories, ENISA category and threat, CWEs, element type, trust-boundary crossing, run id, method and threat id) is shown when editing a risk.
- **SBOM report:** the combined CycloneDX export is renamed **Full BOM (components + crypto + AI)**.
- **App security:** the real-time data connection between browser and server can only be opened from the ***TrustSource*** site itself.
- **App security:** the member list of an organisation carries only non-sensitive fields (name, e-mail and role data).
- **App security:** messages sent by a person are always attributed to that person and scoped to their own organisation, and approvals can no longer reference a project or module of another organisation.
- **App security:** Jira, TFS and webhook URLs that point at internal, private, loopback or cloud-metadata addresses are rejected when saved, and outbound integration requests are re-checked at the moment they are made. Integration credentials are no longer forwarded across a redirect to another host.
- **Component Lake:** the component index search identifies and de-duplicates results by package coordinate instead of display name.

> [!NOTE]
> Saving a Jira, TFS or webhook URL that points at an internal address now fails with an error until it is changed to a public destination. Stored values are checked only when they are edited.

### Fix

- **Vulnerabilities:** the CVE page of the Vulnerability Lake shows the Threat and Environmental sub-scores for CVSS 4.0, and switching between CVSS 4.0, 3.x and 2.0 no longer gets stuck.
- **REST API:** importing the v2 OpenAPI document into AWS API Gateway no longer warns about `GET /core/tests/sarif/{id}`.
- **REST API:** a `GET`, `DELETE`, `OPTIONS` or `HEAD` request sent with a body no longer hangs and fails with 500; the body is discarded.
- **SBOM report:** the SBOM file details page renders correctly in dark mode, and a PDF can be generated after a CycloneDX or SPDX export.
- **Threat modelling:** clicking a diagram node with a threat-count badge lists those threats in the details panel, and the trust-zone and data-flow threat counts match.
- **Administration:** the **Integrations** entry is back in the Administration menu for account and enterprise administrators. See [Integrations](../06-administration/08-integrations.md).
