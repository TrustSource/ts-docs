# v3.3: Release Notes

> **Covers:** v3.3.0 to v3.3.61 (2026‑07‑17 to 2026‑10‑14)
> **Audience:** All users. Items relevant only to administrators are marked.

This page summarizes the ***TrustSource*** v3.3 series. For the complete,
version-by-version list of every change, see the
[CHANGELOG](https://github.com/eacg-gmbh/ts-app/blob/develop/CHANGELOG.md)
in the repository.

## Added

- **CVD cases**: a new **Outbound → CVD cases** area for companies with
  Coordinated Vulnerability Disclosure enabled: a list and detail view for
  the cases held in the connected CVD platform, with case creation directly
  from TrustSource. See [CVD cases](../04-outbound/06-cvd-cases.md) for the
  full workflow, including how to open a case from the Vulnerability report
  or from a CSAF document.
- A CVSS-vs-EPSS risk-overview chart on the **Vulnerability report**, plotting
  every finding by severity score and real-world exploitation probability,
  in both the on-screen report and the exported PDF.
- An advisory (CSAF/VEX) can now record the CVD case it belongs to, so a
  reader can trace a published advisory back to the disclosure that produced
  it.
- New read-only REST endpoints expose CVSS environmental context and SARIF
  test-result data for external security tooling.
- **Risk register upgrades**: every change to a risk is now recorded
  (who, when, old and new value) and listed on a new **History** tab. A new
  **Decision** tab records a documented decision (mitigate, transfer,
  accept, a temporary exception with an end date, or out of scope) with a
  required rationale. Risks also record the **treatment strategy** (Avoid,
  Mitigate, Transfer, Accept) separately from their state, and lists, the
  Overview, widgets and reports group risks as Untreated, In treatment or
  Done. See [Risks](../03-internal/05-risks/index.md).
- The **Risk Overview** shows a development chart (opened, resolved and open
  over 3, 6 or 12 months) and the risks by state, impact class and origin; a
  click opens the filtered list. The Risks list covers the whole company
  when no project is selected and can be exported as CSV.
- **Risk assessment schemes**: a company defines its own impact classes,
  value and ARO scales under **Administration → Policies → Risk assessment**, with
  thresholds such as "decision required", "no acceptance" and a maximum
  length for temporary exceptions. Projects and modules can override parts of
  the scheme on their CIA tab.
- Risks created from a SARIF import or a manual license resolution now carry
  a **proposed impact class** based on the finding's severity and the
  module's CIA requirements; a class you set yourself is never overwritten.
- Responsible users are notified when a risk task becomes overdue, and the
  decision maker when a temporary exception is 14 days from its end. An
  exception that runs out returns the risk to *assessed* for a new decision.
- **Risks from vulnerabilities and OBOM findings**: new project switches
  keep one risk per vulnerability (CVE) and module, or one per OBOM finding
  and deployment. Publishing a VEX advisory moves the matching CVE risk to
  *assessed*, and a risk asks "ready to close?" once nothing reports the
  finding any more.
- Company admins can set a **default vulnerability confidence level** in
  company settings; it applies wherever a project or module has none of its
  own.
- **New project page**: four tiles (Risks, Deployments, Releases,
  Analytics) above the module list. **Deployments** shows the newest OBOM per
  module and deployment and compares two deployments, including their
  findings. **Analytics** charts violations and warnings over the last 12
  months and lists the modules that got worse. The project list's table view
  shows the number of deployments per project.
- **SARIF and CWE**: each imported SARIF test records the CWE assignments it
  was evaluated with and says whether they changed since. Imports beyond the
  risk register limits (200 weaknesses per tool, 8 tools, 400 per import)
  are reported instead of silently truncated, and every SARIF import and
  quality-setting change appears in **Company Logs**. Uploads in the UI need
  the same roles as the API and are limited to 5 MB.
- **CSAF**: published advisory versions are kept unchanged on a new
  "Published versions" list, advisories are checked against the CSAF 2.0
  mandatory tests before publishing, and advisories can be marked
  AMBER+STRICT so the feed serves them only to keys bound to an affected
  product. Each feed key has an access log (kept 365 days). VEX documents
  carry a justification for findings muted as "False positive" or
  "Vulnerable code not in use". See [CSAF](../04-outbound/04-csaf.md).
- The **OpenSSF Scorecard report** can request a Scorecard for every
  component that has none yet, and a DeepScan shows its Scorecard score and
  checks in the scan's top bar.
- SBOM import accepts **CycloneDX 2.0 (draft)** documents; exports stay on
  CycloneDX 1.7. Threat models can be imported from and downloaded as a
  CycloneDX **TM-BOM**. A document with an unsupported `specVersion` is
  rejected with a message naming the version.
- New license flags `cvd` and `cvdself` and the role **CVD Coordinator**
  (available with `cvdself`) control managed and self-managed CVD.
- New public API endpoints map CVE ids to ENISA EUVD ids and back and return
  EPSS scores and history. `GET /compliance/approvals/{approval_id}` returns
  an approval's status, report progress and, once approved, its public
  release key with the SBOM, notice and CSAF URLs, and approvals can be
  listed by project or module.
- New REST endpoints and filters for risks (history, reports, CSV export,
  assessment scheme) and for OBOM deployments; see the
  [REST API](../09-rest-api/03-endpoint-reference.md).
- **Administrators:** ID tokens and user info issued by **Sign in with
  TrustSource** (OIDC) now carry the `amr` claim: `pwd`, plus `otp` and `mfa`
  when the sign-in used two-factor authentication. Single sign-on logins
  carry no `amr`.

## Improved

- Creating, importing or exporting a CSAF document, and opening a CVD case,
  now consistently require compliance manager, manager, security manager or
  account-administrator rights, enforced the same way everywhere, not only
  in the interface. **Administrators:** this may remove access some accounts
  had in practice before; check who in your company uses these pages.
- Company security managers can now see and open CVD cases, the same as
  compliance managers and administrators already could.
- The API-keys copy button now reliably copies the key, or clearly says why
  it could not, instead of silently placing "undefined" on the clipboard.
- SBOM CycloneDX export gained a dedicated AI/ML (AIBOM) option, and the
  combined export is now labelled "Full BOM (components + crypto + AI)".
- SBOM import is more robust: container/distro images with circular
  dependency graphs (e.g. Debian's libc6 ↔ libgcc-s1) and very deep
  dependency chains now import completely instead of failing.
- Billing details saved on Account & Billing now take effect immediately,
  without a page reload.
- The Identity Integration pages now state plainly when no identity provider
  is configured, instead of failing in several confusing ways.
- Registry search now shows Swift and CRAN packages, and their component
  pages open.
- Only managers and compliance managers can start an approval; any member can
  still save a draft. Approving an already approved request returns its
  existing public release key, and approvals made through the API now get one.
- Resolved obligations: **Propagate settings to → All projects / All my
  projects** works again and asks for confirmation first. "All projects" is
  for portfolio managers.
- Product import is all or nothing: an invalid row stops the import before
  anything is created. Product updates accept a parent's id or identifier.
- Deep scan lists cover at most 500 component versions; report pages show
  **Create** only to roles that may create reports.
- The Resolved obligations and Imports pages moved from the project settings
  tabs to the project's **Reports** menu, and the OBOM settings tab is gone.
- Inviting a user into an internal role, or into a role the company is not
  licensed for, is refused.
- Release and API key settings show a key's real scope.
- The unread-messages indicator shows only when there are unread messages
  and updates live.
- A rejected `architecture.md` upload (project settings or
  `POST /core/projects/{project_id}/architecture`) now says why: each
  matched content rule with its line and the matched text, or the verdict
  of the AI content check. An oversized upload names its size and the limit.

## Fixed

- The CVE impact report now describes GitHub Security Advisories (GHSA
  identifiers) with their full severity and description, instead of showing
  an empty entry.
- A license whose text TrustSource doesn't hold now says so and links to the
  official text, instead of showing an empty panel.
- Several stability fixes to dependency lists, compliance reports and
  approval requests in self-hosted/local setups.
- The public SBOM and Notice endpoints now answer failures with the correct
  HTTP status instead of always reporting "200 OK", so integrations can tell
  a missing document from a successful one.
- Approvals of unassigned modules can be created again, and an approval's
  SBOM uses the scan pinned in it. REST approvals are included in the legal
  report.
- Starting an approval no longer gets stuck as pending when the start
  notification cannot be sent.
- Deep scan lists pick up the module's components and licenses and link to
  the right module; SoUP reports list infrastructure and COTS components.
- OBOM risks no longer get a spurious "updated" entry on every scan, the
  affected-resource total in the risk editor shows the true count, and two
  different OBOM findings are no longer merged into one.
- An existing CWE risk no longer loses occurrences when a tool reports more
  than 200 weaknesses.
- Charts draw correctly in dark mode, and a reload or shared link opens the
  risk that was open.
- A SARIF upload that cannot be imported shows an error instead of loading
  forever, and the Company Logs CSV export is safe to open in a spreadsheet.
- The public VEX/CSAF feed no longer fails for a release with a
  vulnerability that has no CVE details; Jira and TFS actions work again.
- Infrastructure components can be scored from the OpenSSF report, and the
  component "Scorecard" action requests a Scorecard only, not a full
  DeepScan.

## Security

- Notification pop-ups now always show their text as plain text, closing a
  path where a relayed message could have run script content in the
  browser.
- Advisory identifiers published in a CSAF/VEX document can no longer be
  reversed to recover internal module identifiers, and can no longer be
  forged: the key used to obscure them now stays server-side only.
- Outbound integration requests (CVD, Jira, TFS, webhooks) no longer follow
  a redirect to a different host while still carrying the original
  credentials or request content.
- Company data shown when creating a CSAF document or a CVD case is now
  established from the signed-in session on the server, not from what the
  browser claims.
- Browser clients can no longer write company, project, module, scan,
  approval, SPDX and many other records directly; every change goes through
  server-side checks of role and company, and actions such as module
  analysis, imports, SARIF uploads and Jira/TFS/GitHub calls are limited to
  your own company.
- Catalog searches and component pages no longer show which user of another
  company requested a Scorecard or a deep scan. The login pages show a
  neutral background.
- Values in notification mails are escaped, SPDX files are visible only to
  the owning company, and the bundled Bootstrap was patched against two XSS
  advisories.
- Rate limits now apply to deep scan list runs and product imports.
