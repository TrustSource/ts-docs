# v3.3: Release Notes

> **Covers:** 3.3.59 (2026-10-11)
> **Source:** the [Updates](../08-personal/01-updates.md) feed in ***TrustSource***.

This page follows the entries of the **Updates** feed for the v3.3 series. Items are grouped as in the feed under **New**, **Improvement** and **Fix**.

## 3.3.59 (2026-10-11)

### New

- **Risk management:** every risk has a full audit trail and documented decisions: mitigate, transfer, accept, a temporary exception with an end date, or out of scope. The treatment strategy is kept separate from the processing state, and the overview has a development chart and a CSV export. Temporary exceptions expire automatically, and responsible users are reminded before deadlines. See [Risks](../03-internal/05-risks/index.md), [Decisions](../03-internal/05-risks/06-decisions.md) and [Risk history](../03-internal/05-risks/09-risk-history.md).
- **Risk management:** configurable risk assessment schemes. Each company defines its own impact classes, scales and thresholds under **Administration → Policies → Risk assessment**, with overrides per project and module. Initial assessments are proposed from the severity and the module's CIA requirements. See [Risk assessment scheme](../03-internal/05-risks/07-risk-assessment-scheme.md).
- **Risk management:** automatic risks per project, off by default: from vulnerabilities (CVE) with VEX integration and "ready to close?" hints, from SARIF weaknesses (CWE) and from OBOM findings. See [Automatic risks](../03-internal/05-risks/08-automatic-risks.md).
- **Risk management:** a new project page with the tiles Risks, Deployments, Releases and Analytics. Compare two deployments based on their OBOMs, and follow violations and warnings over 12 months. See [Deployments](../03-internal/01-projects/03-deployments.md) and [Analytics](../03-internal/01-projects/04-analytics.md).
- **CSAF advisories:** every published version is kept, the CSAF 2.0 mandatory tests run before publishing, and advisories are published to the provider directory that matches their TLP label (WHITE, GREEN, AMBER, RED). AMBER+STRICT advisories are served only to feed keys bound to a concerned product, and every feed read is logged. VEX justifications are carried for muted findings. CSAF feed keys require the CSAF license. See [CSAF](../04-outbound/04-csaf.md).
- **SBOMs and CBOMs:** import of CycloneDX 2.0 (draft) SBOMs and OBOMs. Threat models can be imported and downloaded as a CycloneDX TM-BOM.
- **Vulnerabilities:** public endpoints map CVE ids to ENISA EUVD ids and return EPSS scores and their history. Approvals can be listed and filtered by status, assignee, project and module, and an approved request returns its release key with the SBOM, notice and CSAF URLs. CSAF drafts can be stored through the API. See the [REST API](../09-rest-api/03-endpoint-reference.md).
- **More:** SARIF tests record who imported them and which CWE assignments applied, the DeepScan OpenSSF Scorecard is back, and there are new REST endpoints for approvals, CSAF drafts, risk reports and OBOM deployments.

### Improvement

- **CSAF:** VEX status is derived more accurately from the selected mute reason, and a CVE muted in one module is no longer published as "not affected" for the project's other modules.
- **CSAF:** validation is stricter (CSAF 2.0 schema), so some documents accepted before are now rejected. New advisories start as draft, and a published advisory can no longer be removed.
- **CSAF:** the CSAF feed serves only published advisories. Advisories with a TLP label other than WHITE go to their own restricted directory.

> [!IMPORTANT]
> Earlier releases placed restricted advisories (TLP other than WHITE) in the public directory. Contact TrustSource support to have previously published restricted advisories removed.

- **Risk management:** **Company Logs** record more: risk edits with old and new values, quality-setting changes, SARIF imports and every switch of automatic risk creation. See [Audit logs](../06-administration/07-audit-logs.md).
- **Details view:** Resolved obligations and Imports have their own pages under a project's **Reports** menu. SARIF upload in the UI follows the same role rules as the API.
- **Compliance:** only managers and compliance managers can start an approval; other members are refused and nothing is saved. Any member can still save a draft. See [Request an approval](../03-internal/06-approvals/01-request-approval.md).
- **Component Lake:** Registry Search covers Swift and CRAN (Comprehensive R Archive Network) packages from the component index.
- **Security:** tenant isolation and role checks were tightened across the product. Create, update and notification actions always act as the signed-in user and reach only that company's data. Approvals, SPDX files, deep scans, module imports, release lists and list settings are limited to the owning company and to permitted roles.
- **Security:** mail sending and request logging can no longer be triggered from the browser, notification mails escape HTML, and rate limits apply to deep scan lists and product imports.
- **Security:** the Company Logs CSV export can no longer be read as a spreadsheet formula, and OpenSSF check texts are escaped.

### Fix

- **Compliance:** approvals work again for unassigned modules, include modules in REST legal reports, use the pinned scan for their SBOM, get a release key when approved through the API, and no longer hang when a notification mail fails.
- **DeepScan:** deep scan lists, SoUP reports for infrastructure and COTS modules, and the product import (now all or nothing) return correct results.
- **OBOM:** OBOM risks no longer get spurious updates, show true resource counts, and can be created for every finding.
- **Integrations:** locked Jira and TFS actions work again, and the public VEX/CSAF feed no longer fails for a release with a vulnerability that has no CVE details.
- Release and API key settings show a key's real scope, and the risk register opens directly without "Authentication required".
- A failed SARIF upload shows an error message instead of loading forever, and a test tool added to one project is no longer saved as company-wide.
- **Security:** the bundled Bootstrap library is patched against two XSS advisories, and dependency updates clear the open audit findings except two without a fix.
